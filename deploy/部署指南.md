# 亚马逊门锁售后分析系统 —— 跨电脑 / 新服务器部署指南

> 适用：把整套系统部署到**另一台电脑 + 一个新服务器网站**，日常只需"拖拽更新"。

---

## 一、系统组成（要知道每个文件干什么）

| 文件 | 作用 |
|---|---|
| `index.html` | 网页端全部功能（单文件 SPA：概况 / 可视化图表 / 明细数据 / 售后分析） |
| `convert_doorlock_to_compact.py` | 把 ERP 导出的 Excel 转成网页用的紧凑 JSON（只保留 MS 开头门锁 SKU） |
| `build_supplier_map.py` | 生成 `data/supplier-map.json`（SKU→供应商，含前缀继承、人工指定） |
| `decrypt_xlsx.ps1` | 检测并解除 DLP（绿盾/PayGuard）加密，Excel 读写前调用 |
| `一键更新.bat` | **日常入口**：拖入 xlsx → 解密 → 转换 → 供应商映射 → 双端推送 |
| `sync.ps1` | 推送脚本：把数据推到 GitHub 与服务器（参数来自 `deploy-config.json`） |
| `deploy-config.json` | **部署参数**（服务器地址 / 域名 / GitHub 仓库），换环境只改这里 |
| `exclusions.json` | 停用排除清单（不合作供应商 / 非门锁产品前缀） |
| `supplier_assign.json` | 人工指定系列归属（优先级：采购表 > 人工指定 > 前缀继承） |
| `data/*.json` | 运行数据（明细 25MB、供应商映射、版本号） |
| `deploy/服务器初始化.sh` | 服务器端一次性初始化（建裸仓库 + 自动发布钩子） |
| `新电脑初始化.bat` | 新电脑一次性：写 `deploy-config.json` + 探测 Python + 装依赖 |

**数据流**

```
ERP 导出的合并 xlsx（桌面）
  → 一键更新.bat（解密 → 转换 → 供应商映射）
  → data/after-sale-data-compact.json + version.json
  → sync.ps1（git push 双端）
  → GitHub Pages（备用访问） + 宝塔服务器（主站，post-receive 自动发布）
```

## 二、服务器端部署（一次性）

在**宝塔服务器**上操作：

1. 上传 `deploy/服务器初始化.sh` 到服务器任意目录（如 `/root/`）。
2. 执行（`<站点目录名>` 建议用域名）：

   ```bash
   bash 服务器初始化.sh doorlock.example.com
   ```

   脚本会创建：
   - 站点目录 `/www/wwwroot/doorlock.example.com`
   - 裸仓库 `/www/repo/doorlock.example.com.git`
   - `post-receive` 钩子（收到 `main` 推送自动 checkout 到站点目录）

3. 宝塔面板 → **网站 → 添加站点**：
   - 根目录填 `/www/wwwroot/doorlock.example.com`
   - 纯静态站点，**不需要** PHP / 数据库
   - 域名解析指向服务器 IP；SSL 可在面板一键申请

4. 配置**免密推送**（新电脑 → 服务器）：
   - 新电脑执行 `ssh-copy-id root@<服务器IP>`，或手工把新电脑的 `~/.ssh/id_rsa.pub` 追加到服务器 `~/.ssh/authorized_keys`
   - 验证：新电脑 `ssh root@<服务器IP>` 免密进入

## 三、新电脑部署（一次性）

1. 安装必备软件：
   - **WorkBuddy**（自带 Python，转换脚本会用到）
   - **Git for Windows**
   - **WPS Office**（源表若为 DLP 加密，解密需要它）
2. 把本项目文件夹拷到新电脑任意位置（如 `C:\Users\<你>\WorkBuddy\亚马逊门锁售后分析系统\doorlock-after-sale-analysis`）。
3. 双击 **`新电脑初始化.bat`**：
   - 输入新服务器的 `server_url`（形如 `root@1.2.3.4:/www/wwwroot/doorlock.example.com`）、站点网址、GitHub 仓库（沿用可回车）
   - 脚本自动写入 `deploy-config.json`、记录 `python_path.txt`、检测 Git、安装 openpyxl
4. 配置 GitHub SSH（可选，不用 GitHub Pages 可跳过）：
   ```bash
   ssh-keygen -t rsa -b 4096        # 生成密钥
   # 把 ~/.ssh/id_rsa.pub 添加到 GitHub → Settings → SSH keys
   ssh -T git@github.com            # 验证
   ```

## 四、日常使用（部署完成后）

1. 从 ERP 导出、合并成一份 Excel（含 `售后明细` + `销量明细` 两个 sheet）
2. 把 xlsx **拖到 `一键更新.bat` 上**
3. 看到 `双端推送完成` 即成功；浏览器打开站点 → Ctrl+F5 强刷

> 双击 `一键更新.bat`（不拖文件）会自动找桌面 `亚马逊门锁售后数据_合并.xlsx`。

## 六、常见问题

**Q1. 拖拽后提示 `ModuleNotFoundError: No module named 'openpyxl'`**
脚本已内置自动安装（`subprocess` + `importlib.invalidate_caches()` + user site 兜底）。若仍报错，手动执行一次：

```bat
"%USERPROFILE%\.workbuddy\binaries\python\versions\<版本>\python.exe" -m pip install openpyxl
```

**Q2. 提示"未找到 Python"**
安装 WorkBuddy 后重试；或在项目根新建 `python_path.txt`，写入 `python.exe` 完整路径（单行）。

**Q3. 推送失败 / 服务器 403、Permission denied**
- 检查 `deploy-config.json` 里的 `server_url` 与真实站点目录一致
- 检查免密登录：`ssh root@<服务器IP>`
- 服务器裸仓库路径须与 `server_url` 中一致（`/www/repo/xxx.git` 与 `/www/wwwroot/xxx` 是两处，前者是推送目标，后者是发布目录）

**Q4. 网页数据没变**
浏览器缓存：Ctrl+F5；或核对 `data/version.json` 是否已更新（版本变化会自动清缓存）。

**Q5. 源表读不出来**
源表可能是 DLP（绿盾/PayGuard）加密 —— 保持用 `decrypt_xlsx.ps1` 先解密（一键更新.bat 已自动调用），不要手工用 openpyxl 直接读桌面文件。

**Q6. 想临时停用某家供应商 / 某个系列**
编辑 `exclusions.json`（`sku_prefixes` / `skus` / `suppliers`），下次更新自动排除。
想把某系列**指定**给某供应商：编辑 `supplier_assign.json`。
